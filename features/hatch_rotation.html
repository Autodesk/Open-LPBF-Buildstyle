Hatch rotation and limitation window

If every layer were hatched in the same direction, the melt tracks would lie exactly on top of each other: the residual stress would add up along one axis, and small gaps could line up into channels. The buildstyle turns the hatch by 67° from layer to layer. The optional limitation window keeps the lines away from the gas flow direction, while still giving every layer a new direction.

In Advanced Toolpath Utility

    Try it yourself

    Zoom into your part in the Exposure Preview and step through a few layers: the hatch turns by 67° each time. Then open the profile, expand Hatching › Volume / hull hatching › Rotation, switch the Limitation window on and set a Window angle. Rebuild and step through the same layers.

    The demo measures the line directions of layers 50 to 53 from the toolpath data: 133°, 20°, 87° and 154° without the window; 97.2°, 78.3°, 89.5° and 100.7° with a 30° window across the gas flow (window direction 0°), and it checks that every layer is exposed towards −X. The gas flows along +X (0°). The demo part parts/hatch_plate.stl is generated by tools/make_parts.py.

    Why 67°

    Hatch lines are exposed back and forth, so a direction and its opposite are the same line: directions repeat after 180°. 67 has no common divisor with 180, so layer after layer gets a new direction, and the same one comes back only after 180 layers. A "round" increment like 90° gives just two directions. Try it with the Angle increment slider.

    The limitation window

    The gas flow carries spatter and fumes across the build plate. A line parallel to the flow is scanned, every second time, straight downstream into its own spatter cloud. The window keeps the line direction within a range, by default 120° wide around the perpendicular of the gas flow. The buildstyle does not cut off the directions outside: it squeezes the whole 180° cycle into the window, so every layer still differs from the layer below.

    The window direction is given relative to the gas flow by default, so the same profile works on machines with another gas direction. The gas flow angle itself is a platform parameter.

    Against the gas flow

    The lines of a hatch block are exposed one after another, so the hatch also moves across the part. If it moves downstream, spatter is blown onto powder that is still to be melted in this layer. With Optimized sorting (on by default, in the hatch group) every layer whose lines would move downstream is turned by 180°: the same lines, exposed in the opposite order, so the hatch always moves against the gas flow. The black arrows in the drawing show this order; switch Optimized sorting off and some layers move downstream again. The end of the video shows a layer exposed from +X to −X.

    Start angle and window direction

    The angle of layer n is start angle + (n − 1) · increment. The start angle turns the whole sequence: every layer keeps its distance to its neighbours, only the first direction changes. All angles of the group are hatch angle values: 0° means lines parallel to the Y axis (the line direction is the value + 90°).

    The window direction uses the same convention, so with start angle 0 and window direction 0 the first layer lies in the middle of the window. Relative to the gas flow, 0° means lines across the flow, exposed against it. With Window direction reference set to Absolute the window direction is measured from the +X axis and no longer follows the gas flow. Move the gas flow slider in both modes: relative to the gas flow, the shaded window turns with it; absolute, it stays put.

    Earlier versions of the buildstyle gave the window direction as a line direction, so their default was 90°. The value is not converted: a profile from an earlier version that uses the window with 90° now keeps the lines along the gas flow instead of across it. Set the window direction to 0°.

      How to try a code change
      1. Work on a copy or a git branch of the buildstyle project.
      2. Open the project folder in an editor such as VS Code. ATU writes jsconfig.json and type declarations into the folder, so the editor can offer code completion.
      3. Make the edit, save, compile the project in ATU and rebuild the exposures.
      4. Check the result in the Exposure Preview or the 3D View, like in the video above.
