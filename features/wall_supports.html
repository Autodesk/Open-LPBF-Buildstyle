Wall supports

Wall supports are thin support walls below overhangs. In a sliced layer they are open lines without area, and each line is melted with one single laser track: no border, no hatch. The only setting of their own is a layer skip, to expose them on every n-th layer.

In Advanced Toolpath Utility

    Try it yourself

    Load a part together with its supports (in the input file manager, mark the support file as support). In the parameter profile, expand Wall supports › Layer skip and set Expose every n-th layer. Rebuild and step through two layers in the Exposure Preview.

    In the demo, ATU reports 13 BSID 700 lines with 147 mm on z = 2.01 mm and none on z = 2.04 mm after the change. The demo parts parts/support_table.stl and parts/wall_supports.stl are generated by tools/make_parts.py.

    One scan line per wall

    The demo table sits 4 mm above the build plate on 13 thin walls, 8 in one direction and 5 across. In each layer, every wall is one open line. The buildstyle exposes it as one laser track: 13 lines with 147 mm in total, as ATU reports for z = 2.01 mm. The track itself is the wall, about one melt track wide.

    Expose every n-th layer

    Supports are removed after the build. They only need to hold the part and conduct heat. With Expose every n-th layer = 2 the walls are exposed on every second layer. Set it in the Top view and step to z = 2.04 mm: only the orange sliced lines are left. The Layer skip view shows the rule: a layer is exposed if (layer index − offset) is a multiple of n. Each exposure then has to melt the skipped powder layer too.

    Fewer, longer lines

    Support lines from the slicer can come in many short pieces. Before exposing, the buildstyle connects touching pieces, merges collinear ones across small gaps and sorts the blocks for short jumps, so the laser switches on and off less often. Step through it in the Clean-up view.

    The top view is drawn to scale from the demo walls. The layer skip view is a schematic side view of one wall. The clean-up view is a sketch with five invented pieces; in the demo every wall already arrives as one straight line.

      How to try a code change
      1. Work on a copy or a git branch of the buildstyle project.
      2. Open the project folder in an editor such as VS Code. ATU writes jsconfig.json and type declarations into the folder, so the editor can offer code completion.
      3. Make the edit, save, compile the project in ATU and rebuild the exposures.
      4. Check the result in the Exposure Preview or the 3D View, like in the video above.
