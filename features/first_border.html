First border (beam compensation)

The first border is the outermost laser path of every island. It runs a little inside the part outline, by the beam compensation, so that the melted edge ends exactly on the outline. Walls too thin for that offset get a blocked path along their middle instead.

In Advanced Toolpath Utility

    Try it yourself

    Open the parameter profile of your part (Open Profile in the Exposure Preview), expand First border (beam compensation) and type a beam compensation. Rebuild and zoom into a corner of the Exposure Preview: the red outline of the part stays, the border moves inwards. Thin features show the blocked path along their middle.

    The video uses 0.2 mm, much more than a real beam compensation, so the shift is visible at all. The demo part parts/border_block.stl (a block with a chamfer, a round corner and a 0.1 mm fin) is generated by tools/make_parts.py.

    Why compensate?

    The laser does not melt a line but a track of roughly 0.1 mm width. If the beam centre ran exactly on the outline, half of the track would lie outside and the part would grow all around. The first border therefore runs half a track width inside: the beam compensation, 0.06 mm by default. In the Edge view, set b and the track width w; the melted edge is on the outline when b = w/2.

    All other rings are measured from the same outline: following borders and fill contours further inside, and the hatch starts hatch offset (0.05 mm) inside the innermost ring.

    Thin walls and blocked paths

    The border is the outline shifted inwards by b. A wall narrower than 2 · b disappears in that shift, so neither border nor hatch would melt it. The blocked path fixes this: one open line along the middle of such a region. Open the Thin fin view and make the fin wider than 2 · b: the border then runs around the fin and the blocked path disappears. Untick Blocked paths to see what stays unexposed.

    In the demo the 0.1 mm fin gets a blocked path with b = 0.06 mm. With b = 0.2 mm it starts 0.19 mm inside the block instead of 0.03 mm, and its end moves back from the tip by 0.22 mm instead of 0.05 mm.

    Blocked paths shorter than the minimum blocked path length (0.02 mm by default) are deleted. Raise the slider above the length of the fin's blocked path (about 1.2 mm) and it is removed, and the fin stays unexposed again.

    Direction and start point

    The melt pool and the spatter are not symmetric to the scan direction. Alternate direction every layer reverses the border on every second layer so such effects do not add up on one side. The closed path also starts and ends somewhere, which leaves a tiny seam; the default random start point spreads these seams. Step through the layers in the Direction view.

    The edge and fin views are drawn to scale in millimetres, but the melt track is a simplified half ellipse and the end trim of the blocked path is approximate. The direction view uses the outline of the demo block; the start points are random as in the buildstyle, not the ones ATU picks.

      How to try a code change
      1. Work on a copy or a git branch of the buildstyle project.
      2. Open the project folder in an editor such as VS Code. ATU writes jsconfig.json and type declarations into the folder, so the editor can offer code completion.
      3. Make the edit, save, compile the project in ATU and rebuild the exposures.
      4. Check the result in the Exposure Preview or the 3D View, like in the video above.
